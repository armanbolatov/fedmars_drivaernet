# Working in this repository

Federated optimizers (FedMuon, FedMARS-M, FedOLion against FedAvg, SCAFFOLD-Adam,
FedLion) for a CFD surrogate on DrivAerNet++. `README.md` covers what the methods and
numbers are; this file covers how to work here without invalidating them.

## What must not change

The results in `results/` come from a frozen protocol. Preserve it:

- **The tuning of record is `results/tune_*.json` and `results/optuna/`.** `benchmark.py`
  reads learning rates and local-epoch budgets from those files, not from the method
  yamls. Never edit a recorded selection by hand.
- **Never retune per seed or per row.** Seeds 43/44 reuse the seed-42 hyperparameters
  unchanged; a per-split learning rate comes from `tune_full.py`, nothing else.
- **Never compare errors across settings.** `proxy` (6k points, 150 test cars),
  `full30` (50k points, 30 rounds) and `full` (50k points, 100 rounds) have different
  coefficient scales. Compare within a setting only.
- **Scores.** A benchmark row is the mean over rounds 96-100; a tuning rung is the
  mean at rounds 20, 25 and 30 (`SCORE_ROUNDS` in `tune_full.py`). Selection is on
  drag `c_d` only; lift is reported, never optimised against.
- **Learning-rate grids use only 1e-x / 3e-x values.**
- **Bit-identity of `src/train.py`.** Any edit there must reproduce the reference
  digits of a 6-round proxy run exactly (see "Checking a change"). Evaluation cadence
  and checkpoint/resume are built to keep the trajectory identical; keep it that way.

## Layout and conventions

- `src/train.py` is the whole trainer; `src/eval_ext.py` and `src/forces.py` are the
  metrics; `src/models` builds the network from `configs/model/`. The data pipeline,
  the Transolver and the force integrator come from the separate `cfd_transformer`
  repo (`CFD_ROOT`, default `~/cfd_transformer`).
- `configs/base.yaml` holds the protocol constants and the three settings;
  `configs/method/*.yaml` the per-method structural hyperparameters;
  `configs/model/*.yaml` the architectures. Files matching `configs/method/*_lr*.yaml`
  are generated ladder rungs (ignored by git, except the two schedule-check configs).
- Run directories: `results/runs/<setting>/<split>/<method>_E<epochs>[_K<clients>]_s<seed>[_g<gamma>]`.
  A run is finished only when `summary.csv` exists; `round_stats.csv` alone is a
  partial or dead run. `checkpoint_*.pt` means it will resume.
- `results/tables/` and `results/figures/` are regenerated by `report.py` and
  `plot.py`; run both before quoting numbers. `validate.py` must report no problems.
- Never commit `results/runs/`, `log/`, checkpoints or datasets (`.gitignore` covers
  them). The maintainer reviews and commits; do not commit or push on their behalf.

## Running on the shared GPU server

- Edit locally, copy to the server, run there. The server copy is never the source of
  truth. One background job per `ssh`; a single `ssh` launching several `nohup`s fails.
- A full-resolution run holds ~32 GB for its whole life (cached memory is deliberately
  never released, so a neighbour cannot take it mid-run). Start a run only with 40 GB
  free; at most two of ours per 80 GB card (`--slots 2`).
- Launch through `scripts/run_bench.sh <gpu> <benchmark.py args>`. Runners on
  different cards may share one work list: rows are locked, finished rows are skipped,
  interrupted rows resume from their checkpoint, longest rows go first.
- Use only the cards you have been given. Other people's jobs on the same card are
  not yours to touch.
- Never `pkill -f` a bare pattern from an ssh session: it matches the ssh command line
  itself. Bracket the first letter: `pkill -f "[r]un_bench.sh"`.
- Stop everything of ours:
  `pkill -f "[r]un_bench.sh"; pkill -f "[c]fd_transformer/bin/python scripts/benchmark.py"; pkill -f "[f]edmuon-cfd/src/train.py"`

## Checking a change

```
python -m py_compile src/train.py scripts/*.py
python scripts/benchmark.py --suite headline --gpu 0 --dry-run    # commands unchanged?
python scripts/validate.py
```

For `src/train.py`, run the reference proxy configuration for 6 rounds
(`--max-test-samples 6 --max-train-samples 60 --downsample-size 2000 --num-workers 2
--eval-every 3 --eval-tail 2`, on the `fedmuon` proxy command from a dry run) and
compare `round_stats.csv`: train_loss must read
`4.519563e-01 3.448710e-01 3.034126e-01 2.901453e-01 2.870484e-01 2.857540e-01`.
A killed-and-resumed run must match an uninterrupted one to every digit.

## Running the protocol with another model

Every network is built through `src/models` from `configs/model/<name>.yaml`; nothing
else in the pipeline knows which architecture runs. A model is any `nn.Module` whose
forward takes the batch's input dict (it may read `centroid` and `normal`, both
(B, N, 3)) and returns `{"pressure": (B, N, 1), "wss": (B, N, 3)}` in normalised
units. Loss, metrics, force integration and checkpoints key off those two outputs.

To add one: write `configs/model/<name>.yaml` (a hydra `model:` node plus
`muon_exclude`, the embedding-like layers the Muon family keeps on Adam), put the
class where hydra can import it (`src/models/<name>.py` or the cfd_transformer repo),
then pass `--model <name>` to `tune.py`, `tune_full.py` and `benchmark.py`. Runs land
in `results/runs/<setting>-<name>/`, tuning records in `results/tune_*_<method>-<name>.json`
and `results/optuna/<stage>-<name>_*`, so the Transolver campaign is never touched.
Hyperparameters do not transfer between architectures: run all three tuning stages
before benchmarking. `configs/model/omniarch.yaml` is a ready second model.
